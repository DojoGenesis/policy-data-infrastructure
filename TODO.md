## P0 — Blocking correctness (found 2026-07-28)

- [x] ~~**`/evidence` and `/candidates` rendered as VISUALLY BLANK pages.**~~ — DONE 2026-07-29. 70 of 71 cards sat at `opacity: 0` permanently, even after a full scroll; the content was in the DOM (~19,875 chars on /evidence) but invisible. **Two independent causes.** (1) `motion.js`'s `reveals()` queries `.reveal` once at boot and observes only what exists then — Alpine renders the ~70 cards via `x-for` *after* that, so those nodes were never observed and never got `.in`. Fixed by re-calling `reveals()` in a `$nextTick` after load, the pattern already precedented at `compare.html:2518` and `county.html:2224`. (2) One JS error per page killed Alpine mid-render: `candidates.html:576` referenced an `idx` its `x-for` never declared, and `evidence.html:712` dereferenced `top_need_counties[0].geoid` where exactly 1 of 70 cards has that array empty — `x-show` gates visibility only, Alpine still evaluates `:href` on hidden elements. Verified 0 hidden / 0 pageerrors on both pages in normal and reduced-motion modes [source: Track A]

- [x] ~~**Reveal stagger delay compounded to 5.5s on long lists.**~~ — DONE 2026-07-29. `--d` feeds motion.css's `transition-delay: calc(var(--d,0) * 1ms)` at an 80ms step. On flat lists using raw `idx * 80`, the last card's fade-in did not *start* until 5.52s after being marked `.in` — visually indistinguishable from the blanking bug above. Capped to `idx % 12` on `evidence.html` (grid) and `idx % 8` on `composites.html:915` (single-column stack, reaches 72 rows at county scope). `candidates.html:576` was left at raw `idx` because its index resets per equity dimension and is therefore already bounded [source: Track A + orchestrator]


- [x] ~~**Generated narrative `<h1>` reads "Five Mornings in " — the county name is missing.**~~ — DONE 2026-07-29. Root cause was **not** the template engine: `pkg/gateway/handlers.go` built `narrative.GenerateRequest` without ever setting `ScopeName`, so `defaultTitle()` concatenated an empty string. The CLI path (`cmd/pdi/generate.go`) set it correctly, which is why this reproduced only through the API. Fixed by adding `resolveScopeName()` (GEOID → `store.GetGeography`, falling back to the analysis record's `ScopeGEOID`, then to the GEOID itself, then to a generic label), wired into **both** `handleGenerateNarrative` and `handleServeNarrative` — the latter had the identical bug and was not in the original report. `Engine.Generate` now also normalizes a blank `ScopeName` so every `{{.ScopeName}}` interpolation is covered, not just the title. 5 regression tests added, verified to fail against the old code [source: Track D]
- [ ] **`lib/chat.js`, `lib/api.js`, `lib/domain.js` export via top-level `const`, not `window`.** In a classic script a top-level `const` is a script-scoped lexical binding, never a property of `window` — so `window.ChatAdapter`/`window.PDI` are permanently `undefined` while the bare identifiers work. This silently broke chat's Send button and Enter key for an unknown period (7 guard sites in `chat.html`, all fixed). Any future page reaching for these through `window` hits the same trap. Either assign them to `window` explicitly in the lib files, or document the bare-identifier contract at the top of each [source: chat track, verified live]

- [ ] **`fcc_broadband.go` FetchState/FetchCounty `return nil, nil` — a SILENT EMPTY SUCCESS.** The pipeline records success and loads zero rows, with no error anywhere. This directly violates the repo's own rule (CLAUDE.md, Architecture Patterns): *"Return HTTP 501 for unimplemented interface methods — makes gaps visible, not silent."* Return an explicit unimplemented error instead [source: sources.toml audit, verified at `pkg/datasource/fcc_broadband.go:107`]
- [ ] **CDC PLACES app-token env var mismatch.** The Go adapter reads `CDC_PLACES_APP_TOKEN`; `ingest/fetch_cdc_places.py` reads `SOCRATA_APP_TOKEN`.
