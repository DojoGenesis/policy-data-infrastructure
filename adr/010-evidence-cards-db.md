# ADR-010: Evidence Cards Database Migration

**Status:** Proposed
**Date:** 2026-07-27
**Deciders:** Cruz Morales, Hermes Agent

## Context

Evidence cards are the bridge between policy positions and indicator data. They answer "what does the data say about this policy?" by pairing each of Francesca Hong's 85 policy positions with county-level statistics from PDI's indicator database.

Since April 2026, evidence cards have been served as a static JSON file (`/static/evidence_cards.json`, 70 cards, 166KB) generated by `analysis/evidence_cards.py`. This works for the current single-candidate, WI-only scope but has limitations:

- **No dynamic filtering:** The frontend loads all 70 cards and filters client-side. Adding more candidates or going national makes this untenable.
- **No incremental updates:** Adding a single card requires regenerating the entire JSON file and redeploying the binary.
- **No cross-referencing:** Cards can't be joined with policies, indicators, or analyses via SQL.
- **No API discoverability:** The `/v1/policy/evidence-cards` endpoint doesn't exist — the API catalog is incomplete.

ADR-002 established the `policies` table (migration 008). This ADR extends that pattern to evidence cards.

## Decision

Create an `evidence_cards` table in PostGIS and serve cards through a parameterized API endpoint. The static JSON file remains as a fallback and for initial seeding.

### Schema

```sql
CREATE TABLE IF NOT EXISTS evidence_cards (
    id SERIAL PRIMARY KEY,
    policy_id TEXT NOT NULL,
    policy_title TEXT NOT NULL,
    category TEXT NOT NULL,
    equity_dimension TEXT NOT NULL,
    title TEXT,
    findings JSONB DEFAULT '[]',
    indicators JSONB DEFAULT '[]',
    statewide_context JSONB DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### API

`GET /v1/policy/evidence-cards?category=housing&equity_dimension=housing_affordability&policy_id=FH-HOUS-001&limit=20&offset=0`

Returns `{cards: [...], total: N}`. All query params are optional — omitting them returns all cards with default pagination (limit=50).

### Migration

Number 012 (following 008-policies, 009-cdc-svi, 010-fbi-nibrs, 011-fcc-broadband).

### Seeding

The existing `analysis/output/evidence_cards.json` (70 cards) is loaded into the table via a SQL INSERT script or a Python seed script. The static file continues to be served at `/static/evidence_cards.json` for backward compatibility.

## Consequences

- **Positive:** Filterable API reduces payload size (70 cards → subset by category/equity dimension) and enables server-side pagination.
- **Positive:** Cards can be joined with the `policies` table for richer responses (policy details inline).
- **Positive:** Incremental updates — add a single card via INSERT without regenerating the full JSON.
- **Negative:** JSONB columns for findings and indicators lose some type safety compared to normalized tables. Acceptable trade-off — the schema of findings varies by policy dimension.
- **Negative:** Seeding must happen at deploy time. The Python evidence_cards.py script must be extended to write to PostGIS (currently writes JSON only).
- **Negative:** Mock stores in tests need new methods (`PutEvidenceCards`, `QueryEvidenceCards`).
